1. Executive Summary

This proposal outlines the scope of work, technical approach, project phases, and cost estimate for the design and development of Car Scans — a web-based OCR (Optical Character Recognition) Document Processing and PDF Generation application.

Car Scans will allow end-users to submit one or more document images via drag-and-drop or folder selection. The system will automatically extract structured data from those images using an integrated AI-powered OCR engine, flag items that require human review, allow users to validate uncertain data in an intuitive interface, and finally generate professionally formatted PDF outputs for each processed document.

Integrated AI

At the core of Car Scans are inbuilt AI-powered OCR models that perform intelligent image recognition and text extraction, enabling the system to understand and interpret document content without any manual data capture. This gives Car Scans its AI-driven capability to process, classify, and validate document data automatically, with average per-field confidence scores in the 95%+ range on real-world sample documents.

This is a single SPA (Single Page Application) deliverable with a well-defined set of features designed to streamline document processing workflows and significantly reduce manual data entry.

Estimated Efficiency Impact

By automating field extraction instead of requiring manual transcription, Car Scans is estimated to save approximately 10 minutes of manual data-entry effort per document image captured (assuming a data-entry clerk typing at least at average speed). Extrapolated across a single operator's 8-hour (480-minute) workday, this quickly compounds:

In other words: for every ~48 documents an operator processes through Car Scans in a day, the equivalent of one full 8-hour workday of manual data-entry effort is eliminated — capacity that can be redirected to higher-value work.
2. Project Objectives
  • Enable efficient, bulk image upload via drag-and-drop or folder selection.
  • Leverage integrated AI and Machine Learning to automate data extraction from uploaded images.
  • Classify extracted data by confidence level (High Accuracy vs. Needs Review).
  • Provide a human-in-the-loop review interface for low-confidence documents.
  • Generate standardised, pre-formatted PDF output for all validated documents.
  • Deliver a user-friendly SPA (Single Page Application).
3. Scope of Work

3.1 Feature Breakdown

Feature 1 – Image Upload Interface
  • Drag-and-drop zone supporting single or multiple image uploads simultaneously.
  • Folder selection support allowing users to select an entire folder of images.
  • Supported formats: JPG, PNG, TIFF, BMP.
  • Upload progress indicators per file.
  • Validation of file types and sizes with clear error messaging.
Feature 2 – AI-Powered OCR Processing Engine
  • OCR processing is powered by inbuilt AI-powered OCR models — open-source, deep-learning-based Machine Learning models used for intelligent image recognition and text extraction.
  • These inbuilt AI-powered models operate as the system's integrated AI engine, analysing each image and identifying text regions, fields, and values through neural network-based recognition — with no cloud per-call API costs, as all processing runs locally on the server.
  • The inbuilt models support 80+ languages and, in testing against real-world sample documents for this project, delivered strong field-level accuracy. A secondary AI model is also integrated and can be enabled to automatically cross-check any field the primary model is uncertain about, for further improved reliability where the extra processing time is worth the trade-off.
  • Average per-field confidence scores returned by the inbuilt AI-powered OCR models across tested real-world samples sit in the 95%+ range, reflecting a high degree of reliability in the extracted data before any human review is applied.
  • Per-detection confidence scores are returned natively by the ML model, feeding directly into the High Accuracy / Needs Review classification logic.
  • Automatic field and value detection from each image.
  • Mapping of detected fields/values to a predefined data object/form structure.
  • Batch processing support for multiple images.
  • Processing status indicators (queued, processing, done).
Feature 3 – Confidence Level Classification
  • Per-field confidence scoring returned from the inbuilt AI-powered OCR models, averaging in the 95%+ range on tested real-world samples.
  • Documents where all fields meet a 100% confidence threshold are automatically marked as High Accuracy.
  • Documents where one or more fields fall below the confidence threshold are marked as Needs Review.
  • Confidence metadata stored per document object.
Feature 4 – Document Processing Results Dashboard
  • A results list view displaying all processed images.
  • Each entry displays: filename, processing status, and accuracy classification (High Accuracy / Needs Review).
  • High Accuracy documents are clearly indicated as ready for output — no further user action required.
  • Needs Review documents are flagged and actionable.
Feature 5 – Human Review & Validation Interface
  • For each "Needs Review" document, the user can open a split-view or overlay review screen.
  • The original image is displayed alongside the extracted form data.
  • Fields that did not meet the confidence threshold are visually highlighted (e.g., coloured bounding boxes drawn over the image at the location of the uncertain field).
  • The user can correct or confirm each highlighted field value.
  • Once all uncertain fields are confirmed, the document is marked as validated.
Feature 6 – PDF Generation
  • A "Generate PDF Outputs" button available once all documents are either High Accuracy or manually validated.
  • Each document object is rendered into a predefined, branded PDF template.
  • All PDFs are generated and made available for download (individually or as a ZIP archive).
  • PDF output format and layout are defined in collaboration with the client prior to development.

7. Assumptions & Exclusions

Assumptions

  • The client will provide sample documents and define the expected data object/form schema during Phase 1.
  • The predefined PDF output template design will be approved by the client no later than the end of Phase 1.
  • The system will be deployed and run locally on a WAMP or equivalent local server stack.
  • The client will provide timely feedback during UAT (within 5 business days).
  • The system is intended for desktop use on Chromium-based browsers. Responsive design and cross-browser support are not included in this proposal.

Exclusions

  • Mobile native application development (iOS / Android).
  • User authentication and account management.
  • Responsive design & cross-browser support (desktop Chromium-only).
  • Integration with third-party systems (e.g., ERP, CRM, DMS) unless scoped separately.
  • Ongoing maintenance and support post-handover (available under a separate support agreement).
